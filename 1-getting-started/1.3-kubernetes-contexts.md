# Kubeconfig and contexts

When working with a database, we use what is known as a "connection string." A connection string is a sequence of characters that specifies information about a data source and the means to connect to it.

In Kubernetes, the equivalent of a connection string is a "Context," which contains all the information needed to connect to a Kubernetes cluster. However, a Kubernetes context is not a string, but rather a YAML object stored in a file known as `Kubeconfig`.

Multiple contexts can be stored in a single Kubeconfig file, and each context can be used to connect to a different cluster. The default location of where the Kubeconfig is stored is `~/.kube/config`.

## Check the contents of the Kubeconfig file.
```bash
cat ~/.kube/config
```

## Using the Kubeconfig file with kubectl

When using the `kubectl` command, it will execute within the current context defined in the `~/.kube/config` file. However, you can specify a different context using the `--kubeconfig` parameter or the `KUBECONFIG` environment variable.

```bash
kubectl get pods --context colima
```
To avoid using the `--context` parameter in every command, it is more convenient to connect directly to a cluster.

### Get the list of Contexts
```bash
kubectl config get-contexts
```

### Display the current-context (context in use)
```bash
kubectl config current-context <NAME>
```

### Use Context
```bash
kubectl config use-context <NAME>
```

### Delete Context from Kubeconfig
```bash
kubectl config delete-context <NAME>
```
