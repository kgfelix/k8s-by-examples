# Service

In Kubernetes, services are used to configure networking, such as making Pods accessible externally.
Pods are ephemeral and constantly created or destroyed with changing IP addresses, a Service provides a stable IP address, a persistent DNS name that always routes to healthy pods, no matter how many times they restart or reschedule.

Kubernetes offers four main types of Services, each with specific functionalities:

* ClusterIP: Default type. Use for internal cluster communications, such as backend services, databases, and caches.
* NodePort: Use for limited external access, typically in development environments or where you will implement your own load balancing solution.
* LoadBalancer: Choose this for publicly exposing applications, such as APIs and websites, especially in production environments.
* ExternalName: Ideal for redirecting traffic to external services using DNS.

## Cluster IP

# ClusterIP: internal only

 ```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-demo
  namespace: staging
spec:
  type: ClusterIP # default — can omit this line
  selector:
    app: nginx-demo # must match Deployment template labels
  ports:
    - name: http
      protocol: TCP
      port: 80 # port the Service listens on
      targetPort: 80 # port on the pod container
```

### Apply the Service manifests
```bash
kubectl apply -f nginx-svc-clusterip.yaml
```

### List Services and watch for EXTERNAL-IP to appear
```bash
kubectl get svc -n staging

kubectl get svc -n staging -w
```

# See which pod IPs the Service is routing to
```bash
kubectl get endpoints nginx-demo -n staging
kubectl get endpointslices -n staging -l kubernetes.io/service-name=nginx-demo
```
The -l flag stands for --label-selector — it filters results to only show resources that have a matching label.


# Detailed Service info: selector, events, port mapping
```bash
kubectl describe svc nginx-demo -n staging
```

# Test ClusterIP from inside the cluster
```bash
kubectl run curl-test --image=curlimages/curl --rm -it --restart=Never -n staging  -- curl http://nginx-demo.staging.svc.cluster.local
```

# DNS resolution check
```bash
kubectl run dns-test --image=busybox --rm -it   --restart=Never -n staging   -- nslookup nginx-demo.staging.svc.cluster.local
```
